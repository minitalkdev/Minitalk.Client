# PHP support and database upgrades

The new client requires PHP 8.2, 8.3, 8.4 or 8.5. Upgrade the hosting runtime before uploading the new client files. Keep the previous client package available for rollback. PHP 7.4 users should retain their previous client until their hosting PHP version has been upgraded.

The bootstrap checks the runtime before loading configuration, sessions or database code. PHP below 8.2 receives HTTP 503 with a plain-text hosting upgrade notice. Newer PHP releases are allowed, with an administrator warning until validated. This check cannot prevent a customer from manually replacing files through FTP; do not upload the new package to an unsupported host.

The install screen reads the minimum PHP version (8.2.0) from package.json. Database inspection on an administrator GET is read-only. Schema changes require an authenticated administrator POST, session CSRF token and matching schema hash. No public request applies schema changes.

Supported automatic schema updates are additive: create missing InnoDB tables, add safe columns/indexes, or widen existing character fields using online DDL. Unsafe conversions, MyISAM tables, or unsupported online operations require manual review. Existing configuration and conversation rows are preserved. MySQL/MariaDB DDL is not transactional: successful partial changes remain if a later operation fails, and a retry resumes from the observed schema. The recorded version advances only after verification succeeds.

Testing scope: Docker official php:8.2-cli through php:8.5-cli run syntax checks and HTTP smoke tests for the uninstalled entry point, administrator redirect, installer rendering and PHP dependency endpoint, with E_ALL and log inspection. Installed behavior is now also tested with MySQL 8.0.32 on each of PHP 8.2, 8.3, 8.4 and 8.5: 26 HTTP/integration assertions per runtime, including fresh installation with blank DB port, login, schema version, cloned queries, administrator lists, malformed inputs, full file upload/publication and reinstall prevention. E_ALL log inspection reports no PHP warnings or deprecations in those scenarios. The separate PHP 8.5/MariaDB 10.11 lab retains the 36 schema migration assertions. These checks cover the named scenarios; they do not exhaustively test every application feature.

Release transport compatibility: Socket.IO client 2.5.0 was tested against a legacy Socket.IO 2.3.0 server and the upgraded Socket.IO 4 server with allowEIO3 enabled. The modern server is a separate deployment.
Trusted proxies: configure $_CONFIGS->trustedProxies as an array of exact proxy IPs or CIDRs in Minitalk.preset.php. The default trusts no forwarded headers. GetClientIp validates the peer and every forwarded IP, and walks XFF from right to left across trusted proxies to prevent accepting attacker-prepended addresses. For widget-only pages, configure $_MINITALK->trustedProxies as well. Initialize both configuration objects in the preset before assigning properties, because either bootstrap may load the preset independently. The widget uses $_MINITALK first, falling back to $_CONFIGS only when its own setting is absent. See PROXY-CONFIG.md for an example. Configure only actual proxy subnets; never trust all IPv4/IPv6 addresses. Malformed XFF falls back to REMOTE_ADDR. CloudFront/ALB configurations must include the actual intervening proxy hops if the original viewer IP is needed.
